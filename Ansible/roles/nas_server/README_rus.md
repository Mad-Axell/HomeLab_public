# nas_server

Публикует объявленный набор каталогов через Samba и, по желанию, NFS, и заводит учётные
записи Samba, которым эти ресурсы доступны.

## Роль владеет smb.conf

`/etc/samba/smb.conf` пишется целиком из `nas_server_shares` и глобальных переменных.
Правки на месте заменяются, а не сливаются; перед установкой файл проверяется `testparm`.

Реестр конфигурации Samba роль намеренно **не** подключает. Ресурс, созданный через
Cockpit File Sharing или `net conf`, живёт в `registry.tdb`, где Ansible его не видит, не
диффит и не восстанавливает, — и перестаёт публиковаться в тот момент, когда этот файл
записывается без строки `include = registry`. Поскольку отказ молчаливый, роль читает
реестр и перечисляет всё, что там ещё описано, чтобы оператор перенёс нужное в объявление
и удалил остальное через `net conf delshare`.

## Ресурсы и учётные записи — разные вещи

Samba держит собственную базу паролей поверх системных учёток. Пользователь, созданный
ролью `base_add_users`, войти не может, пока учётка не заведена и здесь, а ресурс с
`valid_users` до этого момента не пускает никого. Сочетание выглядит как рабочая
конфигурация и отвергает любой вход, поэтому роль заранее проверяет, что каждое имя из
`valid_users` и `write_list` присутствует в `nas_server_samba_users`. Имена с `@` — это
группы, их Samba разрешает в момент подключения.

Пароли записываются только для отсутствующих учёток. Базой владеет сама Samba, и
пользователь мог сменить пароль — через `smbpasswd` или через `unix password sync`,
который эта роль включает, — поэтому принудительная запись объявленного значения на каждом
прогоне молча это отменяла бы. Осознанный сброс: `nas_server_samba_force_password: true`.

## Владелец экспортируемых каталогов

Роль создаёт каталоги ресурсов, но владельца им не выставляет. В этом проекте пути
являются датасетами ZFS, владельцем которых распоряжается роль `pve_storage_zfs`; перехват
здесь заставил бы две роли спорить об одном атрибуте на каждом прогоне.

Нормализовать владельца записываемых файлов следует через `force_user` и `force_group` на
ресурсе. Без них на общем каталоге копятся файлы разных владельцев, и следующий
пользователь не может их перезаписать.

## Обязательные переменные

`nas_server_shares` — список ресурсов, у каждого минимум `name` и `path`.
`nas_server_samba_users` — учётные записи, у каждой `name` и `password`.
Для NFS дополнительно нужен `nas_server_nfs_clients`.

Полный список — в `defaults/main.yml`.
