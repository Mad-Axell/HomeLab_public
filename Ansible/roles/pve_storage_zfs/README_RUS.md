# pve_storage_zfs

Роль воспроизводит ZFS-хранилище узла по стабильным путям
`/dev/disk/by-id`. Датасеты управляются модулем `community.general.zfs`,
состояние пулов проверяется через `community.general.zpool_facts`. Команда
`zpool create` используется только для первичного создания пула, поскольку
готового модуля создания zpool в установленной коллекции нет.

Создание отсутствующих пулов заблокировано без двух параметров:

```yaml
pve_storage_zfs_apply: true
pve_storage_zfs_apply_confirmation: CREATE_PVE_ZFS_POOLS
```

Перед применением обязательно проверьте каждый путь к диску. Создание пула
может уничтожить существующие данные. Существующие пулы роль не пересоздаёт.
Датасеты и права также меняются только при `pve_storage_zfs_apply: true`.

## Сверка существующих пулов

Роль создаёт только **отсутствующие** пулы, поэтому пул, собранный иначе, чем
объявлен, иначе остался бы невидимым: он существует, он `ONLINE`, и каждый прогон
сходится зелёным поверх дефекта. Эту дыру закрывают три проверки только на
чтение. Они выполняются и в `--check`, до всякого применения.

| Проверка | Что ловит | Почему чинится только пересборкой |
|----------|-----------|-----------------------------------|
| Топология | Пул собран не той формы, что объявлена | ZFS не переводит пул между топологиями на месте |
| Состав дисков | Верная форма на неверных дисках; пул, созданный по `/dev/sdX` | Объявление больше не описывает железо |
| `ashift` | Пул создан с неверным размером сектора | `ashift` фиксируется при создании vdev навсегда |

Топология читается из `zpool list -vH`. Этот вывод отступает vdev верхнего уровня
и его диски **одним и тем же** табом, поэтому уровни по отступу не различаются;
группа избыточности опознаётся по имени вида `<тип>-<индекс>`, а потомки без
такого имени означают голый stripe. Одинарная чётность сообщается как `raidz1`,
а объявляется как `raidz`, поэтому ожидаемое значение перед сравнением
отображается.

Свойства датасетов в этот список намеренно не входят: `community.general.zfs`
применяет объявленные свойства на каждом прогоне, то есть они сходятся сами.

## Объявляйте каждое локально заданное свойство

Объявление обязано перечислять **все** свойства, выставленные на пуле локально, а
не только содержательные. Роль применяет ровно то, что ей передали, поэтому
свойство, живущее только на диске, теряется молча в момент пересоздания пула.
Проверять так:

```bash
zfs get -o name,property,value,source -s local,received all <пул>
```

Две связки стоит знать. `xattr=on` на актуальном OpenZFS равен `sa`, а не
directory-based хранению, и полезен только вместе с `dnodesize=auto`: при
legacy-дноде в 512 байт расширенные атрибуты перестают помещаться в область
системных атрибутов и сваливаются в directory-based, то есть ровно в то, ради
ухода от чего `sa` и существует. Это важно везде, где Samba хранит DOS-атрибуты
и NT ACL, а SELinux — метки.
