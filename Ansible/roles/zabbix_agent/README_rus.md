# zabbix_agent

## Обе половины или ни одной

Установка агента не делает хост наблюдаемым. Пока на сервере нет объекта хоста,
указывающего на него, ничего не собирается и хост попросту невидим — ни ошибки, ни
предупреждения, только отсутствие. Регистрация хоста без агента — зеркальный случай: хост
появляется в интерфейсе, а все элементы становятся неподдерживаемыми. Поэтому роль владеет
обеими половинами.

## Hostname — это ключ связи

`Hostname` в конфигурации агента обязан совпадать с именем хоста на сервере, буква в букву.
Активные проверки сопоставляются по этой строке и ни по чему больше.

Расхождение — худший для диагностики вид отказа, потому что выглядит частичным. Пассивные
проверки, которые сервер открывает сам по адресу, продолжают работать, поэтому хост
показан доступным и часть данных приходит. Всё активное остаётся неподдерживаемым, и нигде
нет сообщения, связывающего эти два факта. Роль выводит обе величины из одной переменной,
чтобы они не могли разойтись.

## Регистрация выполняется с контроллера

Вызовы API делегируются контроллеру, а не выполняются на наблюдаемом хосте. Наблюдаемой
машине незачем ходить в API Zabbix, а раздача учётных данных API каждой машине, за которой
следят, переворачивала бы смысл наблюдения.

## Шаблоны и группы должны существовать заранее

Имена шаблонов сопоставляются точно, и несуществующий на сервере шаблон - ошибка, а не
предупреждение. Группы хостов роль создаёт при отсутствии, поскольку хост совсем без групп
Zabbix отвергает.

## Drop-in, а не поставляемый файл

Настройки пишутся в `zabbix_agent2.d/`, который поставляемый `zabbix_agent2.conf` уже
подключает. Файл дистрибутива не переписывается и сохраняет всё, что изменит следующая
версия пакета.
